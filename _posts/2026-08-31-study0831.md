## 사용해보기  
![](/postPic/26-08-31/3.png)  
* call state를 클릭하면 특정 함수 진입 부 부터 시작할 수 있다.  
* address에 함수 시작 주소를 입력.  
* signiture 부분의 해당 함수의 시그니처 입력(이 부분은 angr가 파싱해서, 바이너리에서 레지스터를 알맞게 세팅하기위한 용도. 따라서 angr가 이해할수 있는 타입과 함수 이름을 써야함.)  
* 시그니처를 알맞게 입력하면 파라미터 값도 설정가능(비워두면 모든 가능한 값)  
* target address에 도달 가능성을 보고 싶은 주소를 적기(단 하나라도 도달가능하면 그대로 종료되니, 여러 목적지를 확인하고싶다면 여러번 돌려야함)  

**테스트할 드라이버의 함수**  

```c++
__attribute__((noinline, used, optimize("O0")))
VOID* EFIAPI VulnerableProtocolFunction (IN UINT32 X, IN UINT32 Y) {
  UINT32 AllocationSize = X + Y;
  VOID* Buffer = NULL;

  static UINT32 Pool[16];
  Pool[0] = 0xDEADBEEF;

  // 첫 분기: 인자에 의존하지만 수학적으로 항상 참.
  // (n*(n+1) 은 항상 짝수 → 최하위 비트는 언제나 0 → +1 하면 홀수 → 0 아님)
  // 컴파일러가 param 값을 모르면 접을 수 없다.
  if ((AllocationSize * (AllocationSize + 1) + 1) & 1) {
    Pool[1] = 0xCAFEBABE;
    Pool[2] = (X ^ Y);
    Buffer = &Pool[1];
  }

  // 둘째 분기: 인자에 의존하지만 수학적으로 항상 거짓.
  // (n*(n+1) 은 항상 짝수 → &1 은 언제나 0)
  if ((AllocationSize * (AllocationSize + 1)) & 1) {
    Pool[3] = 0x8BADF00D;
    Buffer = (VOID*)(UINTN)Pool;
  }

  return Buffer;
}
```  
이 함수를 포함한 UEFI 드라이버를 EDK2로 빌드하여서 사용하였다.
반드시 참이며 거짓인 분기가 있어 심볼릭 익스큐션 툴을 테스트할 수 있으며  
빌드할 때 최적화 되지 않도록 코드를 짜달라고 부탁한 결과이다.

## 한계점  

gbs -> AllocatePool을 호출하는 부분이 있다고 가정해보자.
AllocatePool을 부를 때, 그 실제 주소에 있는 것은 바이너리에 박혀 있는 게 아니라 부팅 중 펌웨어가 gBS 테이블에 채워 넣는 값이다. 그런데 심볼릭 실행은 펌웨어 없이 드라이버만 떼어 돌리는 것이라 그 테이블이 백지 상태고, call [BootServices+offset]이 가리킬 주소가 비어 있어 angr가  
>'그럼 가능한 주소범위 어디든 갈수 있는건가?'    

    
라고 생각해 갈 곳을 못 정하고 엉뚱한 데로 튀며 뻗는다. 
따라서 stub을 만드는 등 사전작업을 통해 가상의 gBS테이블을 미리 세팅해서 심볼릭익스큐션이 실행가능하게 해줘야한다.  
이래서 쓰려면 UEFI 특화의 심볼릭 익스큐션 도구를 찾아야한다는 것..  
![](/postPic/26-08-31/7.png)  
  
하지만 만약에 결국 이런 도구를 찾는데 실패했다면 클로드의 도움으로 직접 만들 여지도 있다.  
![](/postPic/26-08-31/6.png)  
이렇게 해당 익스텐션에서 커스텀 훅을 넣을 수 있는데, 여기에 '필요한 stub을 만들어줄수 있는 코드'를 만들어서 넣어 준다면 동작할거다.
