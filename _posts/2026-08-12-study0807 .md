**지난 주 심볼릭 익스큐션 툴의 문제**  
* UEFI만 가면 먹통이 됨.  
* 간단한 곳에서 제대로 작동하지 않는 경우가 있었음.  
* 우리가 쓸수있게 커스텀 하긴 적합하지 않았음. (이 베이직 블럭에 도달가능한 바노드 조합이 있는가 까지만.)  

---

## 왜 유명한 툴들은 추천 안해줬을까  

흔히 사람들이 쓰는 angr, CLEE 같은 툴이 있는데. 클로드와 탐색한 해당 툴은 별도로 만들어져 있었고, 또 활용도 쉽지 않았다. 따라서 많이들 쓰며, 커스텀이 쉬운 툴을 쓰는게 더 좋아보였다.  

실제 그 이유가 있었는데. 나는  
* 타겟을 미리 잡고(타겟 지향적)  
* 거기까지 도달가능하게 역으로 함수 시작까지 거슬러 올라가며  
* 도달가능한 값이 있는지 역방향 심볼릭 익스큐션  

이었다. 해당방식의 문제는  

* 역연산의 표현이 애매한 연산이 있을 수 있음. ex) 형변환에 의한 윗쪽 잘림
* 전역변수, 메모리 접근 관련 이슈 (이 값은 전역변수인가 메모리인가..), 포워드는 어렴풋이 파악가능.
* 루프, 재귀를 만나면 골치아파짐. ex)이거 for문을 몇번 돌았지

그래서 이 방식(backward symbolic execution)  실제 구현체는 거의 없었다. 유명하고 일반적인 방식은 위에서 아래로.  

* 시작부분부터 위에서 아래로  
* 모든 경로를 다 살피는 대신에 각종 신경쓸것이 사라짐 (phi노드, 루프..)  
* 경로폭발을 대비한 여러 최적화를 해주고, 툴들마다 이를 내가 선택할수 있게 해줌.
* 구현체 매우 많음(angr, KLEE)  

---

## 선행 연구 확인하기  
우연히 KLEE를 사용해 UEFI를 심볼릭 익스큐션하는 방법을 제시한 유명한 논문을 찾을 수 있었다.  
[STASE: Static Analysis Guided Symbolic Execution for UEFI Vulnerability Signature Generation](https://dl.acm.org/doi/pdf/10.1145/3691620.3695543)   

단순히 심볼릭 익스큐션 부분만 참고하려했으나, 초반 정적분석부분도 우리가 참고할만할듯해, 다음에 한번 읽어서 정리해보려고한다.

해당 연구에서 제시한 도구의 파이프라인.  
![](/postPic/26-08-12/1.png)
* UEFI 소스코드 -> LLVM bitcode에서 정적분석(매우 간단히, 오탐 많게) 
* 각 경우마다 하네스(UEFI 환경 테스트에 필요한 전역변수 세팅, 구조체 내부 안쓰는곳 단순화, 외부함수 호출은 무슨값이든 될수있다고 뭉뚱그려 처리)  
* 심볼릭 익스큐션, 탐지 결과 반환.  


**나의 경우와의 차이는?**  
* 심볼릭 익스큐션 전에 필요한 하네스(전역변수, 구조체) 세팅. -> 아마 이것때문에 저번주툴이 안돌아간게 아닐까.
* 소스가 주어져있다. 그래서 구조체 접근 등을 쉽게 처리가능.  
* 소스를 이용해 LLVM 비트코드로 변환해서 KLEE이용. 나는 기드라 특화된 심볼릭 익스큐션하려함 -> 굳이?  
  
## 개선된 파이프라인

1. pcode 정적분석으로 의심되는 주소를 찾음.
2. 바이너리를 심볼릭 익스큐션용 툴자체에서 리버싱 후 의심 주소에서 심볼릭 익스큐션.(pcode 사용 없음.)

1. **angr** -> angr에서 쓸 vex IR로 바이너리를 리버싱 후 심볼릭 익스큐션. 
2. BINSEC -> 위와 유사, 좋다고는 하는데, 검색해도 깃허브, 레딧 등에 토론 글이 하나도 없음.  

1번이 좋겠다 판단함.
