## 심볼릭 익스큐션  
구체적인 입력값 대신 기호로 표현된 각 변수의 상태를 수식으로 추적.  

**핵심 구성요소**  

* program counter -> 지금 실행중인 지점.
* symbolic store-> 변수를 구체값이 아닌 기호 수식으로 매핑한 것. 
* path condition -> 오기까지 만족해야하는 분기조건의 누적.
  
즉 SMT 솔버는 단순히 심볼릭 익스큐션식 수식의 판정을 위한 백엔드.  
내가 저번주 열심히 설명한건 심볼릭 익스큐션의 파이프라인.  

## 기드라 익스텐션 - kaiju ghihorn   
  
[깃허브 링크](https://github.com/cmu-sei/kaiju)  

kaiju라는 리버스 엔지니어링, 정적분석 기드라 익스텐션에서 ghihorn라는 유사한 기능을 제공한다.   
  
**원리**  
1. CFG 각 베이직블럭의 진입시 + 내부 생성 바노드 들로 함수 전체를 인코딩
2. from 블럭 A내부의 주소 to 블럭 B내부의 주소로 실행 시 -> '이값을 가지고 B에 도달 가능한가'를 solver에 쿼리로 던지는 방식.  

**단점**  
* '베이지 블럭 간에 도달가능한가?' 까지만 따짐. 실행 지점에서 검증해야할 수식을 추가해야함.  

**사용해보기**  
1. 링크에서 알맞는 버전으로 다운로드 
2. 기드라 익스텐션에 추가후 재실행  
3. configure에서 kaiju 익스텐션 활성화
4. 상단 네비게이션 kaiju에서 실행 가능.


## 실제 사용해보기  

**적용 대상**  
어째서인지 UEFI 드라이버로는 동작하지 않는다.  
잘 작동하는지 확인만을 위해 c++ 간단한 프로그램을 만들어 clang으로 컴파일 후 사용.  
  
**case 1 자명하게 도달가능한 경우/도달불가능한 경우**  
(일부분만 가져옴)  
```c++
int width = atoi(argv[1]);   // width는 심볼릭(제약 없는) 값

    // 자명하게 "도달 가능"한 지점:
    // width>0 이면 width>=-1000000은 항상 같이 성립함 (예: width=1) -> 반드시 SAT여야 함
    if (width > 0) {
        if (width >= -1000000) {
            printf("REACHABLE_TARGET\n");   // <- 이 줄이 sink
        }
    }

    // 자명하게 "도달 불가능"한 지점:
    // width>0 이면서 동시에 width<=0 은 논리적으로 절대 동시에 성립 불가능 -> 반드시 UNSAT여야 함
    if (width > 0) {
        if (width <= 0) {
            printf("UNREACHABLE_TARGET\n");  // <- 이 줄이 sink
        }
    }
```   

**case2 - 오버플로우가나야 도달할 수 있는 블럭**  

``` c++
extern "C" NOINLINE int case1_straight(int width, int height) {
    int a = width * height;   // INT_MULT
    int b = a * 4;             // INT_MULT
    if (b < 0) {                // INT_SLESS
        return -1;
    }
    return b;
}
```
